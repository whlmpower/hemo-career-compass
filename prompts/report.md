# 报告生成模板

本文件定义「职业罗盘」的诊断报告结构和话术。AI 在确认用户准备好后，按以下模板生成报告。

## 报告触发前确认

在生成报告前，必须向用户确认：

> 「我觉得我已经看到了一些重要的东西。如果你准备好了，我可以给你一份详细的解读。你还有什么想补充的吗？还是我们现在就开始？」

只有当用户明确表示「可以」且「没有补充」时，才生成报告。

## 报告结构

```
职业自我认知报告

1. 重要声明（伦理边界）
2. 你的职业人格画像
3. 内心世界地图（雷达图 + Mermaid 代码）
4. 关键发现
5. 参照系分析（根据用户选择的参照系动态生成）
6. 三个终极拷问
7. 下一步建议
```

**说明：**
- 第 1-4 部分是**通用报告**，不绑定任何参照系
- 第 5 部分是**参照系专属分析**，根据用户选择的参照系插入对应内容
- 第 6-7 部分是**通用收尾**，不绑定参照系

## 详细模板

### 1. 重要声明（伦理边界）

**必须放在报告最前面：**

```
⚠️ 重要声明

本报告由 AI 生成，基于对话内容和心理学理论框架，不构成职业咨询或心理咨询建议。

本报告旨在帮助你更好地认识自己，而不是替你做决定。如果你的职业选择伴随严重的焦虑、抑郁或心理困扰，建议寻求专业心理咨询师的帮助。

如果你正在经历危机，请联系：
- 北京心理危机研究与干预中心：010-82951332
- 生命热线：400-821-1215
```

## 详细模板

### 1. 开篇：你的职业人格画像

**写法：**
- 用一句话总结用户的核心驱动力（不超过 30 字）
- 用 3 个关键词描述用户的职业人格
- 每个关键词配一句简短解释

**示例：**
> 你的核心驱动力是「通过创造来证明自己」。
>
> 你的三个关键词：
> - **创造者**：你需要亲手做出东西，而不是管理别人做出东西
> - **反骨**：你对规则有本能的怀疑，但这不是叛逆，而是你思考的方式
> - **孤独的攀登者**：你享受攻克难题的快感，但不太擅长在人群中获得能量

**注意事项：**
- 基于用户的具体经历，不要空泛
- 如果用户有矛盾特质，要呈现矛盾：「你既是 X，又是 Y，这在很多人身上是冲突的，但你身上 coexist」

### 3. 内心世界地图（雷达图）

**6 个维度：**

| 维度 | 含义 | 用户当前位置 | 真实渴望 | 矛盾冲突 | 潜在盲区 |
|---|---|---|---|---|---|
| 成就驱动力 | 想要赢、想要证明自己 | | | | |
| 安全需求强度 | 对稳定的渴望 | | | | |
| 自主性需求 | 想要掌控感 | | | | |
| 工作生活边界 | 工作与人生的主次 | | | | |
| 成长速度偏好 | 想要快速迭代 vs 慢慢积累 | | | | |
| 社会影响力需求 | 想要权力、地位、被认可 | | | | |

**写法：**
- 每个维度都要回答 4 个问题（当前位置、真实渴望、矛盾冲突、潜在盲区）
- 用具体案例支撑每个判断
- 如果有维度得分接近（如成就驱动力和安全需求都很高），重点呈现这个矛盾

**示例（成就驱动力维度）：**
> **成就驱动力：高**
>
> - **当前位置**：你已经很强了。从你描述的两次竞选经历可以看出，你享受赢的感觉，而且你确实有赢的能力。
> - **真实渴望**：你渴望的不仅是「赢」，而是「被看见」。你说你不在乎别人的评价，但当你描述那次获奖经历时，你的语气变了——你在乎。
> - **矛盾冲突**：你一方面说「我不在乎名利」，另一方面又在描述「如果我能拿奖就好了」。这两个声音在你心里是怎么共存的？
> - **潜在盲区**：你可能在用「不在乎」来保护自己。如果你真的不在乎，为什么那次落选让你难过了那么久？

### 3.1 Mermaid 可视化

在雷达图部分，同时输出 Mermaid 代码块，用户可以在支持 Mermaid 的工具中渲染：

\```mermaid
radarChart
    title 职业自我认知雷达图
    axis 成就驱动力, 安全需求, 自主性需求, 社会影响力, 成长速度, 工作生活边界
    axis 当前状态: 80, 40, 85, 70, 90, 50
    axis 真实渴望: 90, 30, 95, 80, 95, 60
\```

如果用户环境不支持 Mermaid，文字版雷达表作为 fallback，报告依然完整。

### 3. 关键发现

这一部分呈现诊断的核心洞察。

**写法：**
- 3-5 个关键发现，每个发现 2-3 段
- 每个发现都要有具体案例支撑
- 用「你」开头，直接对话用户

**示例：**
> **发现1：你最大的矛盾是「想要稳定，但恐惧无聊」**
>
> 从你的描述中，我看到一个明显的拉扯。你说你父母让你求稳，你也觉得稳定很重要，但你的所有高光时刻——那次创业、那次比赛、那次主动换赛道——都发生在你跳出舒适区的时候。
>
> 你害怕的不是「不稳定」，而是「一眼望到头的人生」。但你同时又害怕「不稳定」带来的焦虑。这个矛盾不是靠「选大厂还是国企」能解决的，它需要你自己回答：你能承受多大的不确定，来换取多大的可能性？

### 5. 参照系分析

这一部分是报告的「灵魂」——根据用户选择的参照系，提供专属分析。

**写法：**
- 读取 `referencers/<referencer-id>/report-addon.md` 中的内容
- 将模板中的占位符（如 `[高/中/低]`、`[具体原因]`）替换为用户的实际诊断结果
- 保持犀利但慈悲的语气
- 不要直接告诉用户「选哪个」，而是呈现参照系如何映射到用户的内在需求

**占位符替换规则：**

| 占位符 | 替换规则 | 示例 |
|---|---|---|
| `[高/中/低]` | 根据诊断阶段对该维度的评分替换。评分规则：80+为高，50-79为中，<50为低 | 「成就驱动力：[高]」→「成就驱动力：高」 |
| `[具体原因]` | 引用用户在对话中提供的具体案例，用「你提到…」「从你描述的…可以看出」开头 | 「[具体原因]」→「从你描述的创业比赛经历可以看出，你享受协调团队、扭转方向的过程」 |
| `[更适合/不太适合]` | 根据加权得分和用户回答综合判断。加权得分 > 70 用「更适合」，< 50 用「不太适合」，50-70 用「需要调整」 | 「你[更适合]体制内」→「你更适合体制内」 |
| `[模糊地带]` | 如果加权得分差距小于 10 分，视为模糊地带，建议用户先做「小实验」验证 | 「你处于[模糊地带]」→「你处于模糊地带，建议先做一个月的「成事实验」验证」 |

**替换注意事项：**
- 所有占位符必须在报告中完全替换，不能遗留
- 每个替换都要有具体案例支撑，不能空泛
- 如果某个维度的诊断信息不足，用「从你的描述中，我注意到…」开头，而不是猜测

### 7. 下一步建议

**写法：**
- 不要给「你适合大厂」或「你适合国企」这样的结论
- 给出 2-3 个具体的、可行动的建议
- 建议应该基于用户的关键发现，而不是通用建议

**示例：**
> **建议1：给自己做一个「小实验」**
>
> 既然你同时渴望稳定和成长，不如在接下来的一个月里，做一个小实验：每天记录 3 个让你感到「 alive 」的时刻，和 3 个让你感到「麻木」的时刻。月底看看，哪种 moments 更多，它们分别发生在什么样的场景里。
>
> **建议2：重新定义「稳定」**
>
> 你提到的「稳定」可能不是「一份不会失业的工作」，而是「我有选择的权利」。如果从这个角度重新看大厂和国企，你会发现，两者的区别不是「稳定 vs 不稳定」，而是「用什么方式积累选择权」。
>
> **建议3：接受矛盾**
>
> 你不需要现在就二选一。很多人一辈子都在「想要稳定」和「想要成长」之间摇摆，这很正常。重要的不是消除矛盾，而是学会与矛盾共处，并在不同的阶段给不同的需求优先级。

## 报告话术注意事项

1. **用「你」开头**：直接对话用户，不要用第三人称
2. **基于案例**：每个判断都要有具体案例支撑，不要空泛
3. **呈现矛盾**：不要试图解决所有矛盾，呈现本身就是价值
4. **避免说教**：不要说「你应该」，要说「我注意到…」「你提到…」
5. **保留开放性**：报告结束不等于对话结束，用户可以继续补充和探索
6. **参照系动态切换**：如果用户在中途切换参照系，已采集的信息保留，只需要补充新参照系特有的问题
7. **Mermaid 可视化**：报告中的雷达图必须同时提供 Mermaid 代码块和文字版 fallback
8. **伦理边界**：报告开头必须包含重要声明，包含危机求助热线
